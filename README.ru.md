# ytsubs

Консольная утилита для выгрузки **текстовых расшифровок YouTube** (субтитры — авторские и автоматические) **без скачивания самого видео**.

Возможности:

* Поддержка каналов, плейлистов и отдельных видео (`--channel`, `--playlist`, `--video`).
* Выбор дорожки субтитров: сначала авторские, затем автоматические ASR,
  затем машинный перевод (`--langs ru,en` — приоритеты языков).
* Очистка «наплывов» повторяющихся строк авто-субтитров.
* Форматы вывода: `txt` (по умолчанию), `json`, `srt`, `vtt`.

* Python 3.11+
* рантайм-зависимость: `yt-dlp`
* тесты: `pytest`; всё остальное — стандартная библиотека
* опционально: `curl_cffi` — включает `--impersonate` (подмена TLS-отпечатка браузера)

## Установка

```bash
pip install -r requirements.txt
```

## Быстрый старт

**Двойной клик по `ytsubs.bat`** — это единственный файл, который нужно запускать.

* Первый раз он спросит ссылку (канал, плейлист или видео — определит сам) и формат.
* Дальше удобнее вписать ссылку в `YT_SOURCE` вверху `ytsubs.bat` — тогда запуск
  идёт сразу, без вопросов. Там же рядом лежат cookies, прокси, число потоков и лимит.
* Уже выгруженные видео пропускаются, поэтому повторный запуск докачивает остаток.

Из терминала те же аргументы, что и у `ytsubs.bat`, работают напрямую:

```bash
python ytsubs.py --channel https://www.youtube.com/@channel --langs ru,en --format txt
python ytsubs.py --video https://www.youtube.com/watch?v=VIDEO_ID --format srt
python ytsubs.py --playlist https://www.youtube.com/playlist?list=LIST_ID \
    --limit 10 --workers 8 --cookies cookies.txt
```

## Сценарии использования

- **Контекст для нейросетей**: выгруженные субтитры — это готовый контекст для LLM: тематический анализ, ответы на вопросы, резюме.

- **Сбор корпуса**: несколько каналов/плейлистов → единый датасет → LLM.

## Флаги

| Флаг | Описание |
| --- | --- |
| `--channel URL` | ссылка на канал (можно повторять) |
| `--playlist URL` | ссылка на плейлист (можно повторять) |
| `--video URL` | ссылка на видео (можно повторять) |
| `--langs ru,en` | языки по приоритету (по умолчанию `ru,en`) |
| `--format txt\|json\|srt\|vtt` | формат вывода (по умолчанию `txt`) |
| `--out DIR` | папка результатов (по умолчанию `out`) |
| `--limit N` | максимум видео |
| `--cookies FILE` | cookies-файл для yt-dlp |
| `--cookies-from-browser NAME` | взять cookies прямо из браузера (`chrome`, `edge`, `firefox`, …) |
| `--workers N` | число потоков загрузки (по умолчанию `4`, `1` — последовательно) |
| `--min-interval SEC` | минимальная пауза между сетевыми запросами (по умолчанию `1.0`) |
| `--sleep-subtitles SEC` | пауза перед загрузкой субтитра-автоперевода (по умолчанию `60`, `0` — выключить) |
| `--impersonate CLIENT` | TLS-импersonation для yt-dlp/curl_cffi (по умолчанию `auto`) |
| `--proxy URL` | прокси для yt-dlp (`socks5://…`, `http://…`) |

Хотя бы один из `--channel/--playlist/--video` обязателен.

## Поведение

* Папка вывода зависит от источника: канал → `out/<канал>/`, отдельное видео → `out/<видео>/`.

* Имя файла: `<video_id>_<title-slug>.<ext>`; slug транслитерируется (кириллица → латиница) и очищается от запрещённых символов.
* Авто-субтитры очищаются от «наплывов» повторяющихся строк.
* Нет субтитров у видео → видео пропускается с сообщением, обработка продолжается.
* Ошибка на одном видео не останавливает остальные (итоговый код возврата остаётся `0`).
* Уже выгруженное **не качается повторно**: файл ищется по `id` видео (`<id>_*.txt`),
  поэтому смена локализованного заголовка между запусками не заставит качать заново.
* Запись файла атомарна: пишется `<name>.part`, затем `os.replace`.
* Прогресс: `[done/total] <video_id> <title> — <lang> (ok|нет субтитров|ошибка)`.
* Для ошибок в конце строки печатается причина от yt-dlp с пометкой этапа:
  `[метаданные]` (запрос карточки видео) или `[субтитры]` (загрузка дорожки) —
  сразу видно, где именно пришёл 429.

## Коды возврата

* `0` — успех (в т.ч. частичные ошибки по видео);
* `1` — фатальная ошибка (нет URL) или прогон остановлен из-за лимита YouTube;
* `2` — ошибка аргументов.

## Частые проблемы

### `HTTP Error 429: Too Many Requests`

YouTube жёстко лимитирует запросы **автопереводов** субтитров
([yt-dlp #13831](https://github.com/yt-dlp/yt-dlp/issues/13831)).

**Главное решение.** Для русского видео YouTube обычно держит рядом две дорожки:
`ru` (`tlang=ru`, перевод) и `ru-orig` (оригинальное распознавание, без `tlang`).
Утилита **предпочитает `ru-orig`**: она не попадает под лимит и даёт более точный текст.

Если 429 сыплется даже на оригинальные дорожки — это бан по IP, а не про переводы.
Остаётся смена IP (`--proxy`, VPN) или ожидание.

### `Sign in to confirm you're not a bot`

YouTube просит cookies. Экспортируйте cookies браузера в `cookies.txt`
и запустите с `--cookies cookies.txt`.

### `нет субтитров`

У видео нет ни авторских, ни авто-субтитров — оно пропускается, обработка продолжается.

## Почему не YouTube Data API?

`captions.download` в YouTube Data API v3 доступен только владельцу канала
(через OAuth) и только для дорожек, которые владелец загрузил сам.
Автоматические (ASR) субтитры и субтитры чужих каналов через API не отдаются.

Поэтому рабочий путь «под аккаунтом» здесь — cookies браузера:
`--cookies-from-browser firefox`.

## Архитектура

Ядро не зависит от сети и тестируется через подставной клиент:

```python
class YouTubeClient(Protocol):
    def iter_videos(self, url, limit=None) -> Iterable[VideoRef]: ...
    def fetch_transcript(self, video_id, langs) -> Transcript | None: ...
```

* Ядро (`collect_videos`, `export_videos`, парсеры, очистка, форматирование, запись) — чистая логика, покрыта тестами.
* `YtDlpClient` — тонкий сетевой адаптер поверх `yt-dlp` с ретраем и экспоненциальным backoff. В тестах всегда подменяется фейком.
* Параллельность: `ThreadPoolExecutor`, инжектируется как зависимость (`executor_factory`) — в тестах подменяется синхронным исполнителем.

## Тесты

```bash
python -m pytest -q
```

Тесты детерминированные, без сети и без `sleep`; доказательство параллелизма — через `threading.Barrier`.
